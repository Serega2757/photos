# Как загрузить карточки на GitHub и подключить их к боту

## Что внутри

Раз у вас уже все 354 карточки собраны в один архив (из тех частей, что я присылал: `branded_cards_v4_part1.zip` + `branded_cards_v4_part2.zip` + 2 отдельных файла для Chaser и Hype Black) — картинки заново не прикладываю, только:

- `photo_url_mapping.csv` — таблица на 4332 строки (по каждому Артикулу отдельно, как в вашей рабочей таблице), с готовой итоговой ссылкой на картинку для каждого товара. Нужно будет только заменить `<REPO>` на реальный путь после того, как вы создадите репозиторий.
- эта инструкция.

**Важно:** в вашем архиве должны быть те же 5 подпапок-категорий, что и во всех присланных частях — `odnorazky/`, `pody/`, `kartrydzhi/`, `ridyny_gotovi/`, `ridyny_samozamis/` (38 + 100 + 52 + 48 + 116 = 354 файла). Если вы просто разархивировали все части в одну папку — структура должна была сохраниться автоматически, так как во всех частях подпапки назывались одинаково.

## Шаг 1. Создайте (или выберите) репозиторий на GitHub

Если ещё нет отдельного репозитория под картинки — создайте новый **публичный** репозиторий (например, `palmy-card-images`). Публичный — обязательно, иначе ссылки `raw.githubusercontent.com` не будут открываться для Telegram и бота без токена.

Если хотите использовать уже существующий репозиторий бота — можно и так, просто загрузите папку `card_images` как есть, в корень или в подпапку.

## Шаг 2. Загрузите папки через веб-интерфейс GitHub

1. Откройте ваш репозиторий на github.com → кнопка **Add file → Upload files**.
2. GitHub позволяет перетащить (drag-and-drop) сразу **до ~100 файлов за раз**. Все папки, кроме `ridyny_samozamis` (116 файлов), укладываются в это ограничение за один заход. Порядок загрузки (из вашего собранного архива):
   - Перетащите содержимое папки `odnorazky/` в путь `card_images/odnorazky/` в репозитории (GitHub сам создаст папки, если ввести путь в поле выше зоны загрузки).
   - Так же — `pody/`, `kartrydzhi/`, `ridyny_gotovi/`.
   - Для `ridyny_samozamis/` (116 файлов) — придётся загрузить в 2 захода (например, первые ~60 файлов и оставшиеся ~56).
3. После каждой загрузки нажмите **Commit changes**.

## Шаг 3. Получите итоговые ссылки

Как только файлы загружены, ссылка на любую картинку выглядит так:

```
https://raw.githubusercontent.com/<ваш_логин_или_организация>/<название_репозитория>/main/card_images/<категория>/<файл>.jpg
```

Например, если ваш репозиторий `https://github.com/lobodzinskii/palmy-card-images`, то ссылка на конкретную карточку:

```
https://raw.githubusercontent.com/lobodzinskii/palmy-card-images/main/card_images/pody/hd22046.jpg
```

(Если у репозитория основная ветка называется не `main`, а `master` — подставьте `master`.)

## Шаг 4. Пришлите мне название репозитория

Напишите мне что-то вроде: "репозиторий lobodzinskii/palmy-card-images, ветка main" — и я:

1. Подставлю точный путь во все 4332 строки `photo_url_mapping.csv` вместо `<REPO>`.
2. Подготовлю финальный файл, который можно будет вставить (или который я вставлю сам, если дадите доступ) в колонку "Фото" вашей рабочей таблицы "Товари для Helpers" — так бот начнёт брать именно эти брендованные карточки вместо оригинальных фото с сайта.

## Важно про саму таблицу

Колонка "Фото" в рабочей таблице сейчас хранит ссылку на оригинальное фото **для каждой отдельной строки** (SKU/вкус), а не одну ссылку на группу. Поэтому в `photo_url_mapping.csv` я уже подготовил соответствие "Артикул → ссылка на карточку" на уровне **всех 4332 строк** — у всех строк одной товарной группы (одна карточка = один пост) будет одна и та же итоговая ссылка. Это ничего не ломает: бот как брал фото по строке, так и будет брать — просто теперь это будет ссылка на брендованную карточку, а не на оригинал с сайта.
